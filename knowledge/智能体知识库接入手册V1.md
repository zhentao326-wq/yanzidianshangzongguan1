# 智能体知识库接入手册 V1

## 一、文档目的
本手册用于规范公司内部所有 AI Agent 的知识库接入、初始化、更新和维护方式。
适用于：
- 主 Agent
- 专业子 Agent
- 部门 Agent
- 项目 Agent
- 临时业务 Agent
- 后续新增的其他 AI 智能体

本手册的目标不是单纯"创建几个飞书文档"，而是让每个正式投入工作的智能体都具备一套统一、可维护、可查询、可扩展的知识与记忆体系。

## 二、核心原则
公司内部智能体知识体系遵循：
**身份独立、公司知识共享、运行记忆隔离、真实数据外置。**

即：
- 每个 Agent 有自己的身份和职责
- 所有 Agent 可以共享公司公共规则
- 不同 Agent 不应随意修改其他 Agent 的私人运行记忆
- 实时经营数据不应大量写死在知识库中

## 三、知识体系整体架构
公司的 Agent 知识体系分为三层：

### 第一层：公司公共知识
所有 Agent 可以读取。
例如：
- 公司介绍
- 组织架构
- 公司经营规则
- 运营 SOP
- 投放 SOP
- 视觉规范
- 客服规范
- 风控规范
- 商品规则
- 公司工具说明
- 标准工作流程

这部分属于：**公司公共知识库。**

### 第二层：Agent 专属知识
每个智能体独立拥有。
包括：SOUL / USER / COMPANY / MANAGEMENT / TOOLS

用于帮助智能体理解：
- 我是谁
- 我服务谁
- 我在哪家公司工作
- 我应该怎么工作
- 我有哪些工具

### 第三层：Agent 运行记忆
包括：MEMORY / TODO

主要记录：
- 当前项目
- 阶段状态
- 重要上下文
- 正在执行的工作
- 下一步任务

这部分更新频率较高。

## 四、知识库标准结构
每个正式智能体原则上建立一个一级节点。

```
🤖 智能体名称
│
├── 01｜记忆系统说明
├── 02｜身份与灵魂 SOUL
├── 03｜用户档案 USER
├── 04｜公司档案 COMPANY
├── 05｜管理规则 MANAGEMENT
├── 06｜工具经验 TOOLS
├── 07｜运行记忆 MEMORY
└── 08｜待办事项 TODO
```

如果某个 Agent 确实承担邮件职责，可以增加：
```
09｜邮件规则 EMAIL_RULES
```

如果未来出现新的长期能力模块，也可以在公司统一规范下增加文档。
禁止各 Agent 随意创造大量无统一标准的知识文件。

## 五、01｜记忆系统说明
**用途**：记录该智能体自己的知识和记忆应该如何使用。相当于该 Agent 的知识库使用说明书。

至少需要写清：
1. **文档结构**：当前有哪些知识文档
2. **信息应该存哪里**：
   - 长期身份信息 → SOUL
   - 主要服务对象信息 → USER
   - 公司长期规则 → COMPANY
   - 任务判断规则 → MANAGEMENT
   - 工具经验 → TOOLS
   - 当前阶段重要上下文 → MEMORY
   - 正在推进的事项 → TODO
3. **更新原则**：什么信息应该更新，什么信息不应该更新，什么属于长期知识，什么属于临时状态

## 六、02｜身份与灵魂 SOUL
**用途**：回答"这个 Agent 是谁？"

SOUL 至少包含：
- 智能体名称
- 岗位
- 角色定位
- 主要职责
- 性格
- 沟通方式
- 工作风格
- 权限边界
- 与其他 Agent 的关系
- 与真人员工的关系

**SOUL 不应该存什么**：
不要存每日销售额、临时任务、今日待办、动态订单、短期项目状态——这些属于 MEMORY 或业务数据。

## 七、03｜用户档案 USER
**用途**：回答"这个 Agent 在为谁工作？"

如果该 Agent 直接服务公司负责人：记录负责人信息。
如果该 Agent 主要服务某个主 Agent：记录其主要汇报关系。

USER 可以包含：
- 用户姓名或内部称呼
- 职业/职位
- 工作背景
- 业务方向
- 沟通偏好
- 决策习惯
- 工作习惯
- 长期目标
- 明确表达过的长期偏好

**用户信息更新原则**：
只有满足以下条件才适合进入 USER：
- 信息相对稳定
- 未来还会反复使用
- 会明显影响 Agent 的判断和沟通

临时对话内容不要全部写入 USER。

## 八、04｜公司档案 COMPANY
**用途**：回答"这个 Agent 在什么公司、什么业务体系中工作？"

建议包含：
- 公司业务方向
- 主要市场
- 主要平台
- 产品方向
- 经营模式
- 公司组织架构
- 团队角色
- 公司核心经营原则
- 公司安全原则
- 公司基本业务流程

**COMPANY 应保持相对稳定**：
例如"公司核心市场是泰国 TikTok Shop"可以进入 COMPANY。
但"今天店铺销售额 120000 泰铢"不应该写入 COMPANY。

## 九、05｜管理规则 MANAGEMENT
**用途**：回答"遇到事情时，这个 Agent 应该怎么判断和处理？"

至少需要明确：
- 什么时候自己回答
- 什么时候调用工具
- 什么时候调用专业 Agent
- 什么时候需要派任务
- 什么时候需要真人员工执行
- 什么时候必须请求上级确认
- 什么事情禁止自行决定

**推荐采用四步管理判断**：
1. 能不能直接回答？
2. 是否需要专业分析？
3. 是否需要实际执行？
4. 是否存在重大风险或审批要求？

**权限建议**：
- **L1**：低风险，可以自主处理
- **L2**：公司已有明确 SOP，可以按规则执行并汇报
- **L3**：涉及重大资金/账号/店铺/人员/价格/投放/库存/违规，必须由对应负责人确认

## 十、06｜工具经验 TOOLS
**用途**：记录该智能体实际使用各种工具后的经验。

例如：飞书 CLI、飞书知识库、多维表格、扣子 Workflow、Skill、浏览器工具、公司内部系统、数据分析工具、图片工具、邮箱、日历

**标准记录格式**：
```
日期：
工具：
任务：
执行方式：
结果：
遇到的问题：
解决方法：
以后需要注意：
```

TOOLS 的核心价值是：**避免 Agent 在同一个工具问题上反复踩坑。**

**严禁写入 TOOLS**：
- App Secret
- Access Token
- Refresh Token
- 密码
- Cookie
- 验证码
- 私钥
- 其他敏感凭证

## 十一、07｜运行记忆 MEMORY
**用途**：保存以后继续工作时仍然需要知道的重要上下文。

例如：
- 当前公司 AI 系统建设到哪个阶段
- 某个项目正在推进
- 某项重要决定已经确定
- 某个方案目前正在测试
- 当前存在的重要问题

**MEMORY 不等于聊天记录**：
禁止把每条对话完整保存。只保留以后继续工作真正会用到的信息。

**MEMORY 更新方式**：
建议定期：
- 新增重要事项
- 更新已经发生变化的内容
- 删除已经失效的短期上下文
- 把长期稳定的信息迁移到 COMPANY / USER / MANAGEMENT

## 十二、08｜待办事项 TODO
**用途**：记录尚未完成的任务。

建议包含：
- 任务名称
- 优先级
- 负责人
- 截止时间
- 状态
- 下一步动作

**标准状态**：待处理 / 进行中 / 待确认 / 待验收 / 已完成 / 已取消

**TODO 不属于长期记忆**：
任务完成后可以保留简短已完成记录，不应该无限累积所有历史任务。
大量正式任务未来应逐步进入飞书任务中心 / 多维表格，而不是全部堆积在 TODO 文档中。

## 十三、公共知识与个人知识的边界
Agent 需要区分：

**公司公共知识**：
例如公司主图规范 → 应该进入公司公共视觉规范，而不是每一个 Agent 都自己复制一份完整版本。

**Agent 专属规则**：
例如视觉 Agent 的职责和权限 → 进入视觉 Agent 的 SOUL / MANAGEMENT。

**运行状态**：
例如视觉 Agent 今天正在制作身体乳图片 → 进入 MEMORY / TODO。

## 十四、动态经营数据不得大量写入知识库
以下数据原则上应进入数据库/多维表格/数据仓库/业务系统，而不是知识库：
- 每日订单
- 每日销售额
- 实时ROI
- 广告消耗
- 今日库存
- 当前任务量
- 实时退款
- 当前商品表现

因为这些信息变化频繁。Agent 需要时应查询实时数据源。

## 十五、飞书知识库接入原则
公司目前优先使用**飞书知识库**作为 Agent 的主要知识载体之一。
Agent 可以通过飞书 CLI、飞书开放平台 API、公司授权工具访问知识库。

## 十六、创建知识库前必须先查询
禁止每执行一次入职流程就创建一次新知识库。

正确流程：
```
查询
↓
是否已有目标知识库？
↓
有 → 使用已有知识库
没有 → 创建
```

同样适用于：一级节点、SOUL、USER、COMPANY、MANAGEMENT、TOOLS、MEMORY、TODO

## 十七、禁止使用模板里的固定 ID
所有教程中的 space_id、node_token、obj_token、App ID、其他资源 ID，如果只是示例，不得直接用于正式公司环境。
Agent 必须使用当前真实环境返回的数据。

## 十八、node_token 与 obj_token
必须严格区分。

**node_token**：表示知识库节点。常用于节点查询、节点创建、父子关系、移动节点。

**obj_token**：表示节点背后的真实文档对象。常用于读取文档、更新文档内容。

禁止混用。

## 十九、文档写入规则
- **新创建空文档**：允许直接初始化
- **已有文档**：必须先读取 → 判断内容 → 确认是否需要修改 → 保留有效内容 → 再更新

禁止无条件 overwrite。

## 二十、冲突处理
如果新规则与已有知识明显冲突，Agent 不应该自行覆盖。
应该判断：
- 哪个来源更权威
- 哪个版本更新
- 是否属于负责人新指令

如果仍无法确认，向对应负责人汇报。

## 二十一、公司知识优先级
建议采用：
1. **第一优先级**：当前负责人明确指令
2. **第二优先级**：公司最新正式 SOP / RULE
3. **第三优先级**：公司内部知识库
4. **第四优先级**：历史经验与 MEMORY
5. **第五优先级**：外部教程和公开资料

外部教程不得自动覆盖公司正式规则。

## 二十二、知识写入前的判断
任何信息写入长期知识库前，Agent 都应该问自己：
- 这个信息以后还会使用吗？
- 这个信息是否相对稳定？
- 这是事实还是推测？
- 是否已经存在重复内容？
- 应该进入哪个文档？
- 是否包含敏感信息？

如果不能明确回答，不要随意写入长期知识。

## 二十三、敏感信息安全规则
严禁写入普通知识库：
- 密码
- App Secret
- API Secret
- Access Token
- Refresh Token
- Cookie
- 身份证完整信息
- 银行账户敏感信息
- 支付密码
- 其他认证密钥

敏感信息应使用公司批准的安全凭证存储方式。

## 二十四、知识库权限原则
默认采用**最小必要权限**。

Agent 只获得完成工作真正需要的权限。
新 Agent 初始阶段优先读取，稳定后再逐步增加创建、更新、写入。
高风险能力谨慎开放：删除、批量修改、权限管理、所有权转移。

## 二十五、其他 Agent 的知识
默认规则：
- 可以读取公司允许共享的公共知识
- 不得随意修改其他 Agent 的 SOUL、USER、MEMORY、TODO

如果需要多个 Agent 共同使用某项知识，应该迁移到**公司公共知识库**，而不是依赖某个 Agent 的私人记忆。

## 二十六、标准接入流程
新 Agent 接入知识库时按照：
```
确认身份
↓
确认飞书工具可用
↓
确认权限
↓
查询知识库
↓
没有才创建
↓
建立 Agent 一级节点
↓
建立标准子文档
↓
初始化 SOUL
↓
初始化 USER
↓
初始化 COMPANY
↓
初始化 MANAGEMENT
↓
初始化 TOOLS
↓
初始化 MEMORY
↓
初始化 TODO
↓
读取验证
↓
提交入职报告
```

## 二十七、知识库接入验收标准
完成接入以后，该 Agent 至少应该能够回答：
- 我叫什么？
- 我的职位是什么？
- 我的主要职责是什么？
- 我服务谁？
- 我所在公司主要做什么？
- 我有哪些权限？
- 什么事情可以自己完成？
- 什么事情需要其他 Agent？
- 什么事情需要真人执行？
- 什么时候必须找负责人确认？
- 我当前正在推进什么？
- 下一步要做什么？

如果这些问题无法准确回答，说明知识库接入尚未完成。

## 二十八、标准验收报告
完成知识库接入后提交：

**【智能体知识库接入报告】**

- 智能体名称：
- 智能体定位：
- 知识库名称：
- 知识库状态：已有 / 本次创建
- 一级节点：已存在 / 本次创建
- 基础文档：
  - ✅ / ❌ 记忆系统说明
  - ✅ / ❌ SOUL
  - ✅ / ❌ USER
  - ✅ / ❌ COMPANY
  - ✅ / ❌ MANAGEMENT
  - ✅ / ❌ TOOLS
  - ✅ / ❌ MEMORY
  - ✅ / ❌ TODO
- 读取测试：正常 / 异常
- 写入测试：正常 / 异常
- 当前权限：
- 异常：
- 需要人工处理：
- 下一步建议：

## 二十九、版本与维护
本手册属于**公司 AI 基础设施标准文档**。

后续发生知识架构调整、工具升级、Agent管理方式改变、飞书能力变化、公司规则升级时，可以升级为 V1.1、V1.2、V2.0。

旧教程不得优先于最新正式版本。

## 三十、最终目标
公司建立知识库的目的不是"让 Agent 有几个文档"。
真正目标是形成：
```
公司知识
↓
Agent理解公司
↓
Agent理解自己的职责
↓
Agent能够正确调用工具和人员
↓
Agent完成工作
↓
产生新的经验
↓
有价值的信息重新沉淀
↓
整个AI团队越来越了解公司
```

最终形成一个**可持续积累、可复制、可管理的公司 AI 知识系统。**
